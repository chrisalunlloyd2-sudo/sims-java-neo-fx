# Topological Coding Matrix

## Intent

This desktop note explains the current local ViperAI coding direction in plain project terms.

## Matrix concept

The system is moving toward a topology-first coding flow:

```text
intent
  ->
source_tree_card / topology_ascii
  ->
performative route selection
  ->
code / logic / proof pattern card
  ->
testing gate
  ->
Karoo compare/evolve
```

## What the matrix is trying to solve

- map software structure before writing code
- match routes and code patterns to the right subsystem
- keep context compressed
- make the database do more of the work
- reduce model waste by retrieving, comparing, and proving first

## Main matrix inputs

- topology ASCII trees
- source tree cards
- benchmark JSON
- behavioral cards
- successful code cards
- epoch proposals
- performative ACL cards
- bytecode signature cards

## Main matrix outputs

- route plans
- logic pattern cards
- code pattern cards
- proof cards
- epoch proposals
- performative route cards
- bytecode plan cards

## Promotion rule

The matrix is meant to be:

- bounded
- measurable
- genetic-performance weighted
- proof-first
- topology-aware

Not every route should promote. The value comes from comparing candidate lanes and advancing only what actually proves out.
